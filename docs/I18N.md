# 中英文国际化

平台支持简体中文（默认）和英文。右上角语言按钮即时切换，选择保存在当前浏览器的 `umi_locale` 中；刷新及重新登录后继续使用所选语言。切换不刷新页面，也不清空尚未提交的表单。登录、注册页面同样提供语言按钮。

## 前端

- 应用文案位于 `front-end/src/locales/zh-CN/cms.ts`、`en-US/cms.ts`，Umi/Ant Design 内置文案由对应语言包提供。
- 组件调用 `useI18n()` 订阅语言变化，使用 `t()` 读取文案。异步操作在调用时读取当前语言。不要把翻译结果永久存进 state，也不要在模块顶层预先翻译。
- 插值和数量使用完整的 ICU 消息，英文复数使用 `plural`；日期使用 `formatDate()`。Dayjs 和 HTML 的 `lang` 同步更新。
- ProForm、ModalForm、DrawerForm 使用 `useFormLocale()` 的 `formRef`，重新翻译已经出现的校验错误，并保留输入值。
- 请求拦截器及上传组件向本站 API 发送 `Accept-Language`，外部请求不附加平台凭据或语言头。

## 动态菜单

路由、排序、图标、可见性及权限继续由后端提供。新增 `nameEn` / `sys_menus.name_en` 字段，可以在菜单管理中填写英文展示名称：

| 场景 | 展示规则 |
| --- | --- |
| 中文 | 原 `name` |
| 英文且已填写 `nameEn` | 英文展示名称 |
| 内置菜单尚未填写英文 | 根据内置 `locale` 键回退到英文词条 |
| 自定义菜单未填写英文 | 保留原名称 |

内置词条回退只对未改名的内置菜单生效。菜单管理同时显示原名称和英文名称，便于编辑。通知正文、昵称、角色名称、API 描述、日志原始内容等存储数据保留原文，不自动改写或机器翻译。

创建脚本为内置菜单写入中英文名称；迁移 `20260910_cms_i18n_v1` 为已有数据库增加字段，仅回填未改名且英文名称为空的内置菜单。迁移重复执行不会覆盖编辑内容。旧客户端更新菜单时省略 `nameEn` 会保留原值，传空字符串可清空。

## 后端

`I18nMiddleware` 协商 `Accept-Language`，支持中文、英文及其区域变体；不支持或未指定的语言回退到简体中文。业务响应带 `Content-Language`。

HTTP 响应边界统一翻译成功消息、业务错误、鉴权消息及参数校验错误。已有服务错误通过 `pkg/response/message_keys.go` 映射到 `configs/locales/*.yaml`；新增错误可直接使用已有消息键。未知底层错误对外返回当前语言的通用服务错误，保留日志中的诊断信息。

每次请求独立选择语言，不修改全局语言状态；持久化的业务数据和历史审计记录不随查看语言改变。

## 检查与部署

```bash
cd front-end
npm run check:i18n
npm run tsc
npm test -- --runInBand
```

`check:i18n` 检查两种语言的词条齐全性、ICU 语法，以及源码中遗漏的硬编码中文文案。语言自称、注释、开发控制台输出和 `defaultMessage` 不视为遗漏。该检查已接入 CI。

后端执行 `go test -p 2 ./...`、`go vet ./...`；数据库测试使用 `python3 deploy/local/db-matrix.py`。浏览器回归 `front-end/e2e/i18n.spec.ts` 覆盖页面与弹窗切换、登录请求语言、校验、输入保留、刷新持久化、动态菜单和移动端英文布局。通过 `python3 deploy/local/e2e.py` 在隔离数据库运行，避免向共享实例写入测试数据。

升级时先备份，再运行 migrator，最后更新前后端。外部 Grafana 自身的语言设置由 Grafana 管理。
