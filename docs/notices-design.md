# 通知投递语义

公告发布时生成收件人快照：全部用户、指定角色的用户并集，或指定用户。
只包含启用且未删除的用户；多角色命中去重。角色不存在、指定用户无效/禁用或收件人为空时拒绝发布。
角色目标只包含显式分配这些角色的用户，不自动递归子角色。

`targetType` 和去重后的 `targetIds` 记录发布配置，`sys_notice_receivers` 记录实际收件人和首次确认时间。
旧公告保留原收件人，但无法可靠还原原来选择的角色/用户 ID，迁移不伪造这些数据。
后续角色变化、新增用户不影响已发布公告的收件人，包括定时生效公告。

可见时段为 `[startAt, endAt)`：无 startAt 表示立即生效，无 endAt 表示不过期。
开始时间允许过去，结束时间必须晚于当前时间且严格晚于开始时间。
个人列表从 JWT 会话取用户 ID；忽略调用方伪造的 userId。
确认也检查收件人、有效时段和删除状态。无权、不存在、未生效或过期统一返回不可访问，重复确认保留首次时间。

启用“登录时弹出”后，在已登录布局加载时展示有效且未读的弹窗公告，支持多个公告依次展示。
关闭弹窗不确认已读，下一次登录或刷新仍会出现；不会阻断其他工作。
“需确认已读”显示明确的确认按钮和说明；普通公告使用“标记已读”。两者均需用户明确操作，不能用弹窗曝光推断用户读过。
弹窗确认后工作台同步刷新。公告内容按纯文本渲染，不执行 HTML 或脚本。

发布页面切换角色/用户时清空旧目标、重开表单时重置选择、提交 ISO 8601 时间，并刷新发布列表。
接口返回和界面支持中文、英文；用户编写的公告内容不会自动翻译。
基础普通角色只有个人列表和确认权限；发布及全局投递统计需要独立的角色授权。

浏览器和真实 HTTP 安全回归见 `front-end/e2e/token-notice-security.spec.ts`；
SQLite 服务测试及 MySQL/PostgreSQL/SQLite 迁移矩阵覆盖投递统计、确认幂等和有效期。
